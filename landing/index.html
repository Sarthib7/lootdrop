The loop

Allocate → Govern → Choose → Fulfill → Prove

Bitrefill gives agents purchasing power. LootDrop wraps that power in a policy so a community can hand it to an agent without handing over the keys.

01
🎯

Allocate

An admin runs /reward @alice 10, or an AI agent calls create_reward_claim over MCP. No "buy this" command — just intent and a reason.

02
🛡️

Govern

BountyGuard checks max reward, daily/weekly budget, self-reward and category rules. Under the threshold it auto-approves; above it, an admin approves in Discord.

03
🎮

Choose

The recipient gets a private DM and picks country → category → product, capped at their reward value across 170+ countries.

04
⚡

Fulfill

Bitrefill buys the product from the operator balance — autonomous checkout, no human clicks pay. Polling confirms delivery.

05
🧾

Prove

The redemption code lands in the recipient's DM only. A redacted line hits the public audit log — proof without leaking the code.

BountyGuard

A policy engine, not a blank cheque

The hard part of agentic spend isn't buying — it's bounding it. BountyGuard is the layer that lets a community trust an autonomous buyer.

💸 Spend controls

  • ✓ Daily & weekly community budgets, reserved at claim time
  • ✓ Max single reward ceiling
  • ✓ Auto-approve below threshold, human approval above
  • ✓ Category allowlist per community

🚫 Abuse guards

  • ✓ Creator ≠ recipient, approver ≠ recipient
  • ✓ Redemption double-spend guard (one order per claim)
  • ✓ Recipient cooldown window
  • ✓ Agent identity bound at MCP startup, never client-supplied

🔐 Privacy & audit

  • ✓ No redemption codes at rest — fetched on demand
  • ✓ Codes go only to the recipient's DM
  • ✓ Public audit log is redacted by default
  • ✓ Bitrefill API key never leaves the server

🤖 Two ways to drive it

Discord — slash commands, approval buttons and private DMs for humans.

MCP server — identity-bound tools so an AI agent can act safely:

  • ✓ create_reward_claim — allocate within policy
  • ✓ list_reward_budget — read remaining budget, no secrets
  • ✓ list_pending_claims — admin-scoped, codes never included

Mock mode mirrors Bitrefill's documented test products, so the whole loop — search, buy, redeem — runs with zero spend and no API key.

Run it locally

Two processes, mock mode, no funds needed

Node 20+, pnpm 10, and a Discord bot token. Leave BITREFILL_MODE=mock to demo the full flow without spending a cent.

terminal — the bot
# install + set up the local SQLite DB
$ pnpm install
$ cp .env.example .env   # Discord token + IDs
$ pnpm db:migrate && pnpm db:seed

# register slash commands, then run the bot
$ pnpm bot:register
$ pnpm bot
.mcp.json — the agent
"lootdrop": {
  "command": "pnpm",
  "args": ["--dir", "<repo>/apps/mcp-server", "start"],
  "env": {
    "LOOTDROP_COMMUNITY_ID": "<guild id>",
    "LOOTDROP_AGENT_ID": "agent:game-agent"
  }
}

Then in Discord: /reward @alice 10 reason: MVP of tonight's match → Approve → Alice picks a reward in her DM → private code → redacted audit line.
